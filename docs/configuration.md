# Configuration

Static local files live in:

```text
/etc/mnscloud/kamailio-webrtc/
```

Kamailio files live in:

```text
/etc/kamailio/
/etc/kamailio/mnscloud/
```

Nginx TLS files live in:

```text
/etc/mnscloud/kamailio-webrtc/tls/fullchain.pem
/etc/mnscloud/kamailio-webrtc/tls/privkey.pem
```

Additional partner/tenant domains managed from MNSCloud are rendered with their
own certificate material under:

```text
/etc/mnscloud/kamailio-webrtc/tls/domains/<domain>/fullchain.pem
/etc/mnscloud/kamailio-webrtc/tls/domains/<domain>/privkey.pem
```

Nginx renders `/health` on HTTP and HTTPS, redirects regular HTTP traffic to
HTTPS, and proxies secure WebSocket traffic from `https://<public-domain>/ws`
to the local Kamailio WebSocket listener.

The sync process also renders active `RealtimeWebRtcDomain` records returned by the
API. Each active auto-provisioned domain gets a dedicated HTTPS/WSS server block
on `443/tcp` using SNI. The edge supports:

- `letsencrypt`: use an existing Let’s Encrypt certificate or issue one with
  Certbot using the `certbotEmail` value returned by the API. The control plane
  resolves it from `certbot_email`, then the tenant/user email, then the
  platform fallback `no-reply@manaos.cloud`.
- `manual`: use certificate files already placed in the domain TLS directory.
- `self_signed`: generate a temporary self-signed certificate for development.

For Let’s Encrypt HTTP-01 validation, the domain DNS must point to the WebRTC
edge and port `80/tcp` must reach Nginx. The edge serves ACME challenges from:

```text
/var/www/mnscloud-webrtc-acme/.well-known/acme-challenge/
```

The sync process fetches:

```text
GET /api/v1/realtime/webrtc/edge/config
```

Install and update also post runtime metadata:

```text
POST /api/v1/realtime/webrtc/edge/bootstrap
```

This keeps the control-plane server record populated with the physical host
identity, public domain, public/private IPs, base URL, version, and last-seen
timestamp.

Expected server-side request headers:

```text
Authorization: Bearer <server-runtime-token>
X-WebRTC-Node-UUID: <node-uuid>
```

Configuration must be generated by the MNSCloud API. Public examples must use
documentation-safe placeholders only.

## Wildcard certificate for account WSS domains

When the platform enables WSS domains per PABX/Softswitch account (WebRTC › Automatic DNS), the
edge config lists `wildcardCertificates` (`base`, `challengeName`, `status`, `expiresAt`) and the
generated account domains arrive with `certificateProvider=wildcard`. Every sync then:

1. keeps `*.<base>` in `/etc/letsencrypt/live/wildcard.<base>/` with Certbot DNS-01
   (`--manual` + `scripts/acme-dns-hook.sh auth|cleanup`). The hook asks the MNSCloud API to
   publish only the public TXT value of `_acme-challenge.<base>`
   (`POST/GET/DELETE /api/v1/realtime/webrtc/edge/acme-challenges`), waits until every name server
   of the zone answers it and releases it afterwards. The edge never receives DNS provider
   credentials and the private key never leaves `/etc/letsencrypt` on the edge;
2. reports the result (`POST /api/v1/realtime/webrtc/edge/wildcard-certificates`); account domains
   follow it (`issued`/`failed`);
3. renders one SNI server block per account domain using the wildcard certificate, or a temporary
   self-signed certificate until it exists.

Renewal reuses the stored hooks (`certbot renew`, deploy hook `systemctl reload nginx`); a sync
renews when fewer than 30 days remain (`MNSCLOUD_ACME_RENEW_SECONDS`). A failed issuance waits one
hour before the next attempt (`MNSCLOUD_ACME_RETRY_SECONDS`), because Let's Encrypt limits are shared
by every edge. Hook waits: `MNSCLOUD_ACME_API_WAIT_SECONDS` (300) for the platform publication and
`MNSCLOUD_ACME_DNS_WAIT_SECONDS` (300) for the zone name servers. The sync unit has write access to
the Let's Encrypt directories; an MNSCloud Agent update refreshes outdated units.
